# Q6 — LLD rule returns empty array vs error/unsupported: what happens to existing items?
Expected: an empty array from the LLD rule marks every currently-tracked row "lost" (per the
standard LLD lifecycle) but — because lifetime_type/enabled_lifetime_type are both NEVER
(confirmed live, V2) — none of them get deleted or disabled; they simply stop being
rediscovered. Erroring/throwing from the preprocessing script is a DIFFERENT, worse case this
implementation deliberately avoids: nbr_discovery.js wraps its JSON.parse in try/catch and
returns "[]" on any parse failure rather than ever throwing, specifically so a malformed blob
degrades to "no neighbors this run" instead of an LLD rule error state (whose effect on
existing discovered items is less predictable / template-dependent between Zabbix versions and
wasn't separately verified here). Test: push an empty-neighbors blob to a real reporter,
confirm previously-discovered topo.nbr items survive as `status=0`, un-deleted, un-disabled.
