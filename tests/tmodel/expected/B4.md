# B4 — manual link variants
(a) host<->host: expected clean success, one link, discovered_via=manual (or upgraded to lldp
if later confirmed). (b) host<->unmonitored device: expected success too — linkPorts() only
requires ONE end to be a host (§6); the binding to the "d:" side is a plain string, nothing
validates that string actually corresponds to a currently-observed peer. (c) typo'd peer id:
expected SILENT acceptance at write time (no validation) -- the resulting node.id for the typo'd
"d:" side simply never matches anything real, so it renders as an unbound Device with a made-up
key. No error at write time; the mismatch is only visible by comparing the two ends' data.
(d) port already carrying a different discovered neighbor: manual wins, discovered one flagged
conflict=true (already implemented per buildLinks()'s explicit priority rule, but not
exercised end-to-end via the real write endpoint before this campaign).
