# D1 — permissions
Expected: this implementation runs every read through the plain API::*() facade under the
caller's own session (constraint 6) -- a read-only user restricted from host X should simply
not see X in host.get's results, meaning X's chassis/mgmt_ip/tags are invisible to them too.
But X's NEIGHBORS (reported by a host the user CAN see) still carry topo.peer.id/topo.peer.name
tags on items belonging to a host the user CAN see -- so the peer's identity/name leaks even
though the user can't open X directly. Expect this leak to be real and reproducible with a
restricted role; record severity accordingly. A write-capable user changing topo.* tags is
already unauditable beyond Zabbix's own tag-change audit log (no topology-specific change
history) -- confirm this by checking auditlog.get shows the raw tag write with no additional
context.
