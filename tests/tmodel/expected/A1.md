# A1 — neighbor visible, not monitored by Zabbix
Expected: appears as an unbound "d:<chassis>" node (already demonstrated live for
Printer1/UPS2/AP1/AccessSwitch2 in t-model-findings.md). It CAN be labeled via a manual
topo.id/promote onto a placeholder-less string — but per the spec there is no way to pin a
position, attach a note, or mark "ignore" for it: those all need a real Zabbix object to carry
the tag, and an unbound peer has none. Expect these to be confirmed impossible, not just
undocumented.
