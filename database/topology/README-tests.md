# Tests of the topology code (task 046)

One command runs every test that can run on the lab VM:

```
database/topology/run_php_tests.sh zabbix            # MySQL user; MariaDB of the lab, no password
ZBX_UI_USER=... ZBX_UI_PASSWORD=... database/topology/run_php_tests.sh zabbix     # with the checks of the real page
```

It prints `pass` / `FAIL` / `SKIP` per file and a table with the number of checks and the seconds per file. The exit status is 0 when nothing failed. A `SKIP` is a test that needs a state
the lab does not have at that moment; the reason is in the line. Environment: `LABPY` (python with PyYAML and mysql-connector, default `~/work/labenv/bin/python`), `PHPUNIT` (phpunit 8.5 phar,
default `~/work/tools/phpunit-8.5.phar`: 8.5 because `ui/tests/include/CTest.php` calls `TestCase::getAnnotations()`, which PHPUnit 9 removed).

## Run by area (task 119 section 0a)

`run_php_tests.sh --only <areas> <user>` runs only the tests of the areas, comma separated; `--list` prints every test with its areas (`run_php_tests.sh --list`). With no `--only` the run is the full one. The areas are
given by the name of the test (function `areas_of` of the script); a test can be in more than one area.

| area | what | examples |
|---|---|---|
| `ingest` | reconciliation, snapshot, ports of a snapshot | `test_scenario_catalog`, `test_snapshot_ingest`, `test_port_*`, `test_far_*` |
| `links` | links, contradiction | `test_device_links`, `test_link_replacement`, `test_topology_model` |
| `identity` | identity keys, normalization, candidates, classes | `test_identity_*`, `test_normalization`, `test_device_class` |
| `bind` | Bind to interface | `test_bind_interface.php`, `bind_check.py` (both modes) |
| `manual` | manual Device | `test_manual_device.php`, `manual_device_check.py` |
| `junction` | the Junction projection | `test_junction.php`, `junction_check.py` |
| `native` | the native step, the LLD JavaScript, push | `step_golden/*`, `test_generated`, `test_lld_js`, `test_push.py`, `device_rows_check.py`, `test_snapshot_clock.py` |
| `view` | the graph code without a browser | `test_topology_graph.js`, `test_node_label`, `test_leaf_groups`, `test_freshness` |
| `page` | every check of the real page (headless Chrome) and the HTTP checks of the page | `ui_check_040/*`, `lab/php/*_http_check.php`, `graph_page_check.php` |

Examples: level 1 of a task about Bind: `--only bind,view`. About the page: `--only page`. About ingest: `--only ingest,links,identity`. A test of a new area is added in `areas_of`.

### C1, the corpus replay (task 135; lab spec 2.42 §9 C1)
Not in `run_php_tests.sh`: the corpus stand needs the office stand down and ends with it down, so it runs after the common run, with `lab/run_c1_core.sh` (it restores R1 at the end).

Page checks (098): `run_php_tests.sh` runs every check of the real page with a limit of 900 s (`PAGE_TIMEOUT`). The limit, "chrome did not start", a failed login and a run without any result line are infrastructure errors: the check is run once more and the summary counts them apart ("infrastructure: <n>", status INFRA when the second run fails the same way). A check that fails is never retried. The overlap check (also inside `--check arc`) keeps the evidence of a failure in `/tmp/topo_evidence/<time>-<pid>-<check>/` (`TOPO_EVIDENCE_DIR`): `evidence.json` (overlapping pairs with px, node and label boxes, label places, node positions) and `screenshot.png`.

Data of a check (task 109, 110): a page check asserts only on the data it made itself: its own link ids, its own Devices (`ISP-Router`, `BIND-TEST`, ...), and removes them by their ids in a `finally`. It does not count "the manual links in the database" or "the manual Devices in the database": somebody can make one by hand on the stand while the harness runs. A check that must see the whole database says so in its text (for example "no edge has a missing end node": a dangling edge is a defect whoever made it). The stand is checked once, at the start of `run_php_tests.sh` (section 4a): a manual Device or a manual link that no check made is reported as `infrastructure` with its id (`/tmp/topo_t_r1_dirty.log`), the checks that read the stand are not run, and nothing is deleted; the stand is restored from `--reset` by whoever runs it next.
